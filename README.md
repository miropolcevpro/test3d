# WebAR визуализатор плитки / мощения

Проект — рабочий WebAR‑продукт для визуализации мощения в браузере.
Базовый публичный сценарий рассчитан на **Android Chrome / ARCore / WebXR**, при этом каталог, страницы форм, галереи, быстрый запуск и не‑AR часть интерфейса доступны как обычное веб‑приложение.

## Что есть в текущей сборке

### Публичный frontend
- главная страница с каталогом форм;
- quick AR rail / быстрый вход в визуализацию прямо из каталога;
- страницы форм с hero, галереей, техблоком и CTA;
- выбор текстур и безопасная подгрузка контентных URL;
- fatal UI state вместо системного `alert()` при критической ошибке инициализации.

### AR runtime
- сканирование пола / hit-test / фиксация поверхности;
- постановка точек по полу и построение контура;
- заливка зоны выбранной формой и текстурой;
- переключение раскладки: `straight` и `diagonal`;
- вращение текстуры;
- snapshot / снимок результата;
- **многозонный режим**: несколько зон мощения в одной сцене;
- активная зона, редактирование зоны, удаление зоны;
- undo последней точки и cancel текущего draft без потери уже готовых зон;
- anti-overlap validation;
- snap к вершинам и рёбрам;
- seam-safe stitching между зонами;
- вырезы по зоне;
- **бордюры** как edge-based слой по внешнему контуру активной зоны;
- выбор всего периметра или отдельных внешних сегментов;
- усиленная толщина бордюра относительно ранних сборок (+20% от старой базы).

### Админка и операционный слой
- `/admin/` — вход по логину/паролю;
- список форм и палитр;
- bucket library по форме;
- загрузка файлов поштучно и ZIP/structured ZIP;
- auto-add в палитру;
- sync текстуры из bucket в palette;
- удаление из палитры / bucket;
- настройка texture params;
- bulk-операции по параметрам;
- telemetry dashboard, telemetry error report и export;
- confirm overlay для destructive actions;
- улучшенные статусы upload / sync / delete.

### Валидатор палитры
- реальная рабочая страница валидатора: `/admin/palette-validator.html`;
- валидатор доступен **только из админки и только при активной admin-сессии**;
- публичный корневой `palette-validator.html` оставлен как redirect-gate и не является самостоятельной публичной точкой входа.

## Актуальные ограничения
- Полноценный AR‑режим зависит от поддержки WebXR `immersive-ar` и hit-test на устройстве.
- Основной production-сценарий AR — **Chrome на Android** с поддержкой ARCore.
- На iPhone/iPad текущий WebXR-сценарий не считается основным production-path; для iOS нужен отдельный сценарий визуализации.
- В текущей production-сборке пользовательские раскладки ограничены `straight` и `diagonal`; legacy `stagger` нормализуется в `straight`.

## Быстрый запуск в AR
На главной странице есть горизонтальный блок **«Быстрый запуск в AR»**.
Он собирается из опубликованных палитр и использует тот же стабильный launch-pipeline, что и обычный вход через detail-screen.

Текущий приоритет порядка в ленте:
1. Брусчатка
2. Новый Город
3. Старый город
4. Антика
5. далее остальные формы

Под quick rail размещена отдельная CTA-кнопка запуска визуализации.

## Локальный запуск
Статика должна открываться через http(s), иначе загрузка JSON и ассетов будет блокироваться браузером.

Из папки проекта:
```bash
python -m http.server 8080
```

Открыть:
```text
http://localhost:8080
```

## Развёртывание
Проект собирается как статический release-пакет и корректно работает:
- на корневом хостинге (`https://example.com/`);
- в подпапке GitHub Pages (`https://user.github.io/repo/`).

Для упаковки текущей версии:
```bash
python3 scripts/release_check.py
python3 scripts/package_release.py --output dist/3d_release.zip
```

## Контент
- `tiles.json` — базовые плитки и материал-параметры;
- `shapes.json` — формы, карточки, hero/галереи и связи с палитрами;
- `assets/palettes/*.json` — локальные палитры;
- bucket / palette контент дополнительно обслуживается через admin runtime.

При сбоях сетевых палитр и невалидных ассетах приложение использует safe fallback-сценарии и не должно падать целиком из-за одной проблемной записи.

## Service Worker
В проекте используется облегчённый service worker для контроля версий и обновлений сборки.
Он не является основным cache-слоем для JSON/текстурного контента и не должен подменять живые данные палитр.

## Архитектура JS
Runtime разбит на helper-модули в `js/`, а `js/app.js` остаётся orchestration-слоем для screen flow, AR entry и XR loop.
Краткая карта модулей поддерживается в `js/MODULE_STRUCTURE.md`.

## Release discipline
Текущий release token хранится в `RELEASE_STAMP.txt` и должен совпадать с локальными `?v=` токенами в entrypoint-файлах.
Изменения по релизам фиксируются в `CHANGELOG.md`, а ритуал сборки описан в `docs/RELEASE.md`.
